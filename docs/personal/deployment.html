中心与 MISAKA 是两个进程，可以同机也可以分机。数据库与历史只在 MISAKA 所在机器，中心不保存任务与历史。

二单机安装

  1. 准备 Python 3.12 以上环境。安装包依赖随发行物一起提供，不需要系统级包管理器。
  2. 安装 MISAKA，确认版本与命令可用。
  3. 安装中心，初始化数据目录，启动服务。
  4. 在中心建立三个身份：Last Order、一个执行者、一个管理身份。每个身份只拿到一次令牌。
  5. 在中心登记接收目标：Last Order 一个，执行者按实例登记；目标类型为本机回调。
  6. 在 MISAKA 的环境里写入中心地址、令牌、本机回调地址与身份名： MISAKA_CENTER_URL、MISAKA_CENTER_TOKEN、 MISAKA_INBOX_URL、MISAKA_CENTER_IDENTITY。
  7. 运行 misaka state bootstrap 建立第一个协调者模板与实例。
  8. 运行 misaka inbox serve --port 8710 起回调，或交给服务管理。
  9. 指定一个项目目录，启动会话。

完成以上八步后，人在会话里说话即可唤起 Last Order，无需再做任何手工配置。

三中心

中心的职责只有投递：身份、订阅匹配、排队、限频合并、重试。安装与配置按下述顺序：

npm install -g notifs@0.2.0
notifs init
notifs start
notifs identity add last-order
notifs identity add worker
notifs identity add operator --manager
notifs endpoint put --config '{"name":"last-order","owner":"last-order","delivery":{"kind":"webhook","config":{"url":"http://127.0.0.1:PORT/messages"}}}'

执行者的目标由 MISAKA 在建立实例时创建，不在安装阶段手工登记。订阅同理：卡片的订阅随卡片建立与删除，只有 Last Order 自身的订阅在安装时登记一次。

中心默认只监听本机。对外部署必须在前置代理处终结加密，见第六节。

五服务化

需要长期运行的有两个进程：中心与 MISAKA 的后台。两者都用用户级服务管理，开机自启，日志写入数据目录。

服务启动命令重启策略
中心中心自带的启动命令总是重启，间隔 5 秒
回调misaka inbox serve --port 8710总是重启，间隔 5 秒
MISAKA 后台打开面板与后台的命令总是重启，间隔 5 秒

会话窗口是前台进程，由人启动，不做服务化：它属于交互，不属于常驻。

两个服务之间没有启动顺序要求：MISAKA 在中心不可用时照常本地工作，消息暂存。

六专机部署

中心单独放在一台机器时，改动只有三处：监听地址、加密、令牌。

  • 中心监听地址改为可达地址；默认只监听本机。
  • 在中心前面放一层加密代理，或使用内网；中心本身不提供加密。
  • MISAKA 的中心地址改为代理地址；令牌通过文件或环境变量提供，不写入项目目录。
  • 防火墙只放行代理端口；中心端口不对外。
  • 令牌轮换：在中心轮换身份令牌后，更新本机配置并重启后台。

数据库与历史仍在 MISAKA 机器上，不上中心。因此中心换机不影响任务与历史，只影响消息队列。

七升级与回滚

升级分两种：MISAKA 升级与中心升级，互不要求同时进行。

对象升级方式回滚方式
MISAKA替换环境内的包；数据库版本不一致时拒绝启动换回旧包；数据库按备份恢复
中心替换包并重启；队列保留换回旧包并重启
数据不做迁移；版本不一致时要求清空从备份恢复整个数据目录

本产品处于开发阶段，数据不保证向前兼容。升级前先备份数据目录；版本不一致时以清空重建为准。

八备份与恢复

需要备份的只有三处：数据目录、项目目录、中心的配置与队列。

  • 数据目录：数据库与实例会话。停后台后整目录复制，或使用数据库自带的备份命令。
  • 项目目录：产物与卡片导出文件；按普通代码仓库备份。
  • 中心：配置与队列；只影响未投递消息，丢失后重发即可。

恢复顺序：先恢复数据目录，再启动后台，最后确认中心可达。恢复后不需要重建模板与实例。

九排障

现象检查处理
说话没有反应会话进程是否在；数据库是否可写重启会话；检查数据目录权限
卡片不启动前置是否完成；实例是否被占用；代次是否过期按视图提示修正；重新提交启动
订阅不生效中心内是否有对应订阅；目标地址是否可达在中心查询订阅；检查回调端口
消息重复进入接收端是否按编号去重；是否重启过中间层检查去重记录；确认编号来源一致
中心不可达服务是否在跑；端口与令牌重启服务；核对配置
实例被占用无法启动新卡是否有执行中的卡片结束或取消该卡；或另建实例
数据库版本不符启动日志中的版本清空重建，或恢复匹配版本的备份

十安全边界

  • 令牌只存文件或环境变量，权限 600，不写入项目目录、不进入消息与日志。
  • 中心默认不加密、只监听本机；对外必须经加密代理。
  • 接收端在写入持久记录后才确认接收，避免中间层重试造成丢失。
  • 执行者的文件范围与禁止命令由卡片声明，属提示与装配层约束，不承诺阻断所有路径。
