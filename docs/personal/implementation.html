一改动原则

已经能满足设计的部分不动。只改三类：与设计冲突的存储、缺失的能力、为新增能力让路的删除。凡是“换个位置更整齐”的整理，都不做。

因此以下部分完全不动：人与 Last Order 的会话、面板、后台守护、会话装配、实例会话归属、研究流程、文档索引、技能装载、派工与认领、命令行入口。

三新增文件与类

文件类职责方法
messaging/client.pyCenterClient与中心通信，本机与远程两种连接send、health、pending
messaging/sync.pySubscriptionSync把数据库中的订阅推给中心，删除时撤销apply_card、clear_card、apply_instance
messaging/inbox.pyInbox接收投递、按编号去重、注入实例会话accept、seen、inject
context/tags.pyExperienceTag卡片结束时标记一段历史为经历tag、list
context/isolation.pyHistoryIsolation把选定历史收在一个根节点下，此后默认不展开isolate、visible_roots
context/skills.pySkillCandidate技能候选的提交、复核与版本propose、review、publish

新增的三个目录各只有一个职责，不互相依赖；messaging 依赖订阅表，context 依赖历史层，两者都只读工作模型，不写卡片状态。

六关键调用顺序

事件到达。中心 → 本机回调 → Inbox.accept（按编号去重）→ 查到目标实例 → 注入会话。
启动卡片。协调工具 → 校验代次与就绪 → dispatch 认领 → SubscriptionSync.apply_card → 会话装配 → worker 执行。
结束卡片。worker → 状态落库 → SubscriptionSync.clear_card → 释放实例。
建实例。协调工具 → 三种输入之一 → 需要时先建版本节点 → 建实例并返回编号。
隔离历史。HistoryIsolation.isolate → 历史层建根 → 组装时只取可见根。

七阶段与顺序

阶段文件完成标志
零 清理tasks.py、work.py、instances.py从空库建库；无覆盖字段；无旧卡片文件读取
一 版本树work.py、instances.py、wiring/coordination.py三种输入各建一个实例；节点有父版本
二 卡片与订阅tasks.py、dispatch.py、worker.py启动建订阅，结束删订阅；范围与禁令落库
三 工具面instance_part.py、wiring/network.py、coordination.py默认工具集生效；节点显式增加的工具可用；管理工具只给 Last Order
四 通信messaging/*、messages.py事件能到达实例；重投不重复；人不回复无影响
五 上下文动作context/*标签、隔离、技能候选可用
六 视图canvas.py、view.py视图与数据库一致；引用进对话可读

八验收

  • 从空目录建库并启动，确认无旧字段被读取。
  • 三种输入各建一个实例，读取确认节点与实例的对应关系。
  • 建一张带订阅的卡片并启动，中心可查到订阅；结束后订阅消失。
  • Last Order 尝试改文件与执行命令时工具不存在；建卡与启动可用。
  • 关掉中心后本地仍可建卡与执行；恢复后消息补投且不重复。
  • 视图与数据库一致；卡片换实例重新执行可继续。
