二包职责与依赖方向

包职责允许依赖
core/work配置与状态的唯一读写；事务；约束platform（连接与路径）
core/network/coordination把管理动作暴露成工具；参数校验work、messaging
core/network/dispatch启动检查、认领、释放、会话装配work、platform、subagent
core/messaging发布、订阅同步、接收、去重、暂存work（只读订阅）、中心
core/context打标签、隔离、技能候选platform、subagent、documents
ui 与 cli只读查询、会话输入work、dispatch

依赖单向：cli/ui 依赖 work；coordination 依赖 work 与 messaging；work 不依赖任何上层。中间件（messaging）不依赖 coordination，避免循环。

三类设计

core/work

类职责主要方法
WorkStore连接、事务、约束开关；对上层隐藏连接细节open、transaction、close、check_schema
Schema建表与版本校验；不一致时拒绝启动ensure、version、reset_for_development
TemplateTree节点派生、查询、删除约束derive(parent, config)、node(id, revision)、children、latest(id)、list(id)、delete_if_leaf
InstanceRegistry三种创建输入、占用与释放、会话指针create_from_node、create_from_patch、create_from_scratch、get、occupy、release、set_session、archive_session、list
RequestBook请求的建立与版本推进create、update(expected)、get、list_by_owner
CardBook卡片、依赖、状态迁移、代次save_plan、get、list_by_request、start、finish、cancel、bump_generation、ready_cards
SubscriptionBook订阅的增删查；按归属批量替换replace_for_card、clear_for_card、replace_for_instance、list
EventLog追加与按卡片读取append、list_by_card

core/network/coordination

类职责主要方法
TaskTool计划查询、保存、启动show、save、start
RosterTool模板与实例管理show、create_template、derive_template、create_instance
SubscriptionTool订阅管理（Last Order 自身与卡片）show、set、drop
MessageTool向实例或人发消息send、publish

四个类都只做参数校验与调用编排，业务约束在 work 层。工具装配时只注册给角色为 Last Order 的实例。

core/messaging

类职责主要方法
CenterClient与中心通信；本地通路与远程通路两种实现send、health、pending
SubscriptionSync把数据库里的订阅推给中心，删除时同步撤销apply_card、clear_card、apply_instance
Inbox接收投递、按编号去重、写入实例会话accept、inject、seen

core/context

类职责主要方法
ExperienceTag卡片结束时标记一段历史为经历tag、list
HistoryIsolation把选定历史收在一个根节点下，此后默认不展开isolate、visible_roots
SkillCandidate提交技能候选、复核、生效与版本propose、review、publish

执行与视图

类职责主要方法
Dispatcher启动前检查、认领事务、订阅建立、释放start、claim、release
CardRunner在实例会话中执行卡片，写产物与事件run、abort
TaskView只读查询，供画布与命令行共用graph、card、instances、subscriptions
SessionHost实例会话的打开、加锁、切换与归档open、lock、rotate、archive

四表结构

templates(id, revision, parent_revision, role, config_json, created_at,
          primary key(id, revision))

instances(id, template_id, template_revision, label, retired,
          session_epoch, session_file, agent_id, writer_pid, writer_identity, writer_token,
          created_at,
          foreign key(template_id, template_revision) references templates(id, revision))

instance_sessions(instance_id, epoch, session_file, archived_at,
                  primary key(instance_id, epoch))

work_requests(id, workspace, title, body, owner_id, revision, created_at,
              foreign key(owner_id) references instances(id))

tasks(id, request_id, instance_id, generation, title, body,
      fs_scope, forbidden_commands,
      reviewer, verdict, verdict_evidence,
      status, workspace, priority, created_at, started_at, finished_at,
      foreign key(request_id) references work_requests(id),
      foreign key(instance_id) references instances(id))

task_dependencies(child_id, parent_id, primary key(child_id, parent_id))

subscriptions(id, card_id, instance_id, source, type, target, created_at,
              check((card_id is null) != (instance_id is null)))

events(id, task_id, kind, payload, generation, run_id, created_at)

unique index instances_one_card on tasks(instance_id)
  where status in ('running','review');

约束：模板节点不可改；实例必须对应存在的节点；卡片必须属于请求；依赖只能同请求内且无环；一个实例同时只有一张执行中的卡片。

五关键调用顺序

人说话。cli/chat → 会话 → 消息入 Inbox（本地输入不需要中心）→ Last Order 一轮 → TaskTool/RosterTool 写库。

事件到达。中心 → webhook → Inbox.accept（去重）→ 查询该目标的实例 → 注入实例会话；目标为 Last Order 时注入协调会话。

启动卡片。TaskTool.start → CardBook.start（校验代次与就绪）→ Dispatcher.start（校验身份、归属、实例空闲）→ SubscriptionSync.apply_card → 会话装配 → CardRunner.run。

结束卡片。CardRunner → CardBook.finish → SubscriptionSync.clear_card → Dispatcher.release → 事件追加。

建实例。RosterTool.create_instance → 三种输入之一 → TemplateTree.derive（需要时）→ InstanceRegistry.create → 返回编号与版本。

隔离历史。HistoryIsolation.isolate → 历史层建根节点 → 上下文组装时只取可见根。

七验收

  • 从空目录建库并启动，确认无旧字段被读取。
  • 三种输入各建一个实例，读取后确认节点与实例的对应关系。
  • 建一张带订阅的卡片并启动，中心可查到订阅；结束后订阅消失。
  • Last Order 尝试修改文件与执行命令时工具不存在；建卡与启动可用。
  • 视图与数据库一致；引用进对话后 Last Order 能读到对象。
  • 实例异常终止后，卡片能换实例重新执行。
