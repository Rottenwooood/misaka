二数据结构

数据库是配置与状态的唯一权威。以下是本次涉及的表，字段为最小集合。

templates(
  id, revision, parent_revision, role, config_json, created_at,
  primary key(id, revision)
)

instances(
  id, template_id, template_revision, label, retired,
  session_epoch, session_file, writer_pid, writer_identity, created_at,
  foreign key(template_id, template_revision) references templates(id, revision)
)

work_requests(
  id, workspace, title, body, owner_id, revision, created_at
)

tasks(
  id, request_id, instance_id, generation,
  title, body,
  fs_scope, forbidden_commands,
  reviewer, verdict, verdict_evidence,
  status, workspace, created_at, started_at, finished_at,
  foreign key(request_id) references work_requests(id),
  foreign key(instance_id) references instances(id)
)

task_dependencies(child_id, parent_id, primary key(child_id, parent_id))

subscriptions(
  id, card_id, owner_instance_id, source, type, target,
  created_at,
  check((card_id is null) != (owner_instance_id is null))
)

events(id, task_id, kind, payload, generation, created_at)

约束：每个实例必须对应一个已存在的模板版本；一张卡片只绑一个实例；一个实例同时只能有一张处于执行中的卡片；依赖只能在同一请求内。

卡片文件不再保存状态，只作为数据库内容的导出视图，可随时重建。

三关键流程

创建实例的三种输入。只给版本：读取该版本，建立实例。给版本加修改参数：先在该版本下建立新版本节点，再建立依附它的实例。给全部参数：从零建立一个版本节点，再建立依附它的实例。三者都只产生一个实例。

建卡。协调层提交请求、卡片、依赖与订阅；一次事务提交；校验引用、无环、实例存在、路径合法。

启动。按卡片编号与代次启动；检查调用者、归属、代次、前置全部完成、实例无其他执行中卡片；通过后建立订阅并进入执行。

结束。写状态与结论；删除卡片订阅；释放实例；产物留在项目目录。

投递。发送方写中心；中心按订阅投递；接收方按消息编号去重后写入实例会话；失败留在中心重试。

上下文动作。打标签：卡片结束时把这段历史标记为经历。隔离：把选定历史收在一个根节点下，此后默认不展开。技能候选：提交一条带适用范围的方法，复核后生效。

四阶段与顺序

阶段内容完成标志
一模板树与实例：版本增加父版本；删除实例级覆盖；三种创建输入三种输入各能建立一个实例，且实例不带覆盖
二卡片范围与订阅：文件路径、禁止命令、订阅字段；订阅随卡片建立与删除一张卡启动时订阅出现，结束后消失
三协调工具面：建卡改卡、模板与实例管理、订阅管理、发消息；移除文件与命令工具协调实例无法修改文件与执行命令，管理工具可用
四上下文动作：打标签、隔离历史、技能候选与复核卡片结束后可打标签；隔离后默认不再展开；技能候选可复核生效
五清理：删除旧派工工具、卡片文件权威、旧阶段说明仓库内只剩三份文档与实现

五验收方式

每一阶段用同一套方式验收：从一个真实入口开始，走完整链路，记录输出。入口是命令行会话或面板操作，不是内部函数。

  • 阶段一：分别用三种输入建立实例，再读取实例确认其版本与会话。
  • 阶段二：建一张带订阅的卡片并启动，在中心查询订阅存在；卡片结束后再查，订阅已删除。
  • 阶段三：让协调实例尝试修改文件与执行命令，确认工具不存在；再让它建卡并启动。
  • 阶段四：结束一张卡片后打标签；隔离一段历史后开新会话，确认默认不展开；提交技能候选并复核。
  • 阶段五：删除后从空目录安装，按文档走一遍，确认无残留路径。

六删除清单

  • 实例级配置覆盖的读写路径。
  • 旧派工工具与批量派工入口。
  • 把验收、等待、监督写进状态机的分支。
  • 卡片文件作为权威的读写路径，只保留导出。
  • 四份阶段说明，内容并入本文。

七依赖

通知中心作为外部依赖，需要具备：身份令牌、订阅增删改查、按目标限频合并、至少一次投递、无匹配订阅时明确拒绝、按目标的待处理量查询。

缺少的部分按下列顺序处理：先确认现有版本是否已提供；未提供则在中心侧增加最小字段或接口，不在本仓库复制一份通信实现。
