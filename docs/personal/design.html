设计

这个系统有哪些对象、每个对象的行为与边界、结构上必须成立的条件，以及为此付出的代价。不含文件与类，不含安装与运维。

2026 年 11 月　·　三份文档之一

一目标

把 MISAKA 改造成以 Last Order 为入口的代理框架。输入是人的话或订阅事件；Last Order 被唤起后只能做管理动作，不能修改文件、不能执行命令；执行由依附模板版本的实例完成。

对外暴露的工具按对象的本名命名，一次只表达一件事：卡片叫卡片、实例叫实例，不出现同一对象的第二个名字；参数与返回值对称，读回来的形状可以原样写回去；不返回恒常字段，不重复表达同一事实。

系统提供能力，不规定方法。任务怎么拆、要不要监督、由谁验收，都属于提示与模型能力，不进入机制。这一条决定了后面所有取舍：凡是把某种做事方法写进状态机或流程的设计，都不做。

明确不做：编排引擎、验收流程、超时与重试策略、多层权限链、旧数据兼容、多机共享同一份状态。

对象之间只有一个强绑定关系：实例依附模板节点。其余关系都是引用，可以断开而不破坏对方。

三一次输入的生命周期

输入到达有三种来源：人在会话里说话、订阅事件命中、人从视图里引用一个对象后说话。三者最终都变成一条消息，进入同一个会话。

  1. 唤起：消息进入 Last Order 的会话，触发一轮处理。没有消息就没有轮次，系统不轮询。
  2. 理解与决定：Last Order 判断这次要不要做事。它可以只回答人，也可以什么都不写。系统不要求每次输入都产出卡片。
  3. 管理动作：需要做事时，它创建或修改请求、卡片、依赖、订阅，或创建模板节点与实例。这些动作一次提交，提交前校验引用、依赖无环、实例存在、路径合法。
  4. 启动：卡片不会因为被写下而开始。启动是一次单独的显式动作，携带卡片编号与执行代次。
  5. 执行：实例在自己的会话中完成卡片，在卡片声明的项目目录里改文件、跑命令，产物留在项目里。
  6. 结束：卡片进入完成或失败；订阅删除；实例释放，仍可被后续卡片复用。
  7. 呈现：视图从数据库读出最新状态；人可以在视图中看到，也可以引用某个对象继续对话。

事件输入与人的输入只差一步：事件不需要人转述，直接进入会话；人可以在任何时候插话，两者在同一条会话里排队处理。

四模板版本树

模板是一个命名的配置序列，配置本身不可变。每次修改产生一个新节点，节点记录父节点。因此一个模板的全部版本构成一棵树。

  • 任意节点都可以派生新节点，默认从最新节点派生。
  • 不合并两个节点，不改写已有节点的内容或父节点。
  • 不能删除仍有子节点或仍有实例依附的节点。
  • 实例固定在一个节点上，不随最新节点移动。

为什么是树而不是线性序列：需要同时保留几条不同的配置路线时，线性序列只能覆盖最新一条，旧路线会被迫重新录入。为什么不做合并：合并要解决两个配置之间的冲突，收益低，复杂度高。

创建实例有三种输入，都只产生一个实例：只给一个已有节点，直接用它的配置；给一个已有节点加修改参数，先在该节点下建新节点，再建依附它的实例；给全部参数，从零建节点，再建依附它的实例。第二种是日常用法，第三种用于新建一类角色。

第二种输入会产生一个只被一个实例使用的节点。这是有意的：任何差异都留下可复现的记录，而不是藏在实例里。

五实例

实例是执行者，也是上下文的持有者。它记录：编号、标签、依附的模板节点、会话指针、会话代次、当前占用的卡片、写者身份。

规则：

  • 编号唯一且稳定，出现在它发出的每条消息与每条执行记录中。
  • 同一时刻只服务一张卡片。已经开工的卡片即使停在中途，也继续占用实例。
  • 可以被多张卡片先后复用；跨项目复用意味着工作目录随卡片切换，而会话与历史连续。
  • 只有 Last Order 能创建实例。
  • 实例本身不带配置覆盖。任何配置差异都在模板节点上。
  • 没有被任何卡片引用的实例可以删除；删除释放的是配置与路由，不是工作。
  • 没有被实例钉住、也没有后继版本的模板节点可以删除；模板的历史只在仍被引用时保留。
  • 补丁与父节点合并后若没有实际差别，就沿用父节点，不产生新版本。

为什么实例要独立于卡片：卡片是一次性的，实例是持续的。若上下文跟着卡片，则每张卡都要重建历史，复用无从谈起；若上下文跟着实例而实例又绑死一张卡，则实例无法承担第二件事。

六卡片

卡片是一次子任务的完整表示，字段为：所属请求、任务描述与文字边界、绑定实例、执行代次、文件系统范围、禁止命令、订阅、依赖、结论与依据、状态。

状态有五个：待决、就绪、执行中、完成、失败、取消。迁移只有这些：

从到条件
待决就绪全部前置卡片完成
就绪执行中显式启动，且检查通过
执行中完成 或 失败执行结束
未完成取消人通过 Last Order 表达

前置失败或取消不算完成，因此不会让后续卡片就绪。这是唯一由系统保证的推进规则。

执行代次是并发保护：卡片在未开工时被修改，代次加一；启动必须携带当前代次，过期的启动请求被拒绝。这样修改与启动不会交错。

卡片必须自足：换一个实例重新执行时，仅凭卡片内容就能继续。凡是依赖某个实例私有记忆才能继续的卡片，视为卡片没写清任务。

产物属于项目，不属于实例。删除实例不删除产物，也不删除卡片。

七权限：两件不同的事

模板决定能力：有哪些工具、加载哪些技能、用哪个模型、会话如何装配。

卡片决定范围：可以访问哪些文件路径、禁止执行哪些命令。

范围只约束文件与命令，不约束进程能读到的环境。凭证不进入卡片会话的 shell：键名含 KEY、TOKEN、SECRET、PASSWORD 的环境变量在子进程启动前移除；只读实例不能靠 env 读到密钥，也不能把它们写进上下文。

两者互不约束，也不构成上下层。它们回答不同的问题：能做什么，与能碰哪里。

角色只决定身份特权，不决定能力。管理类工具（建卡、模板与实例、订阅、发消息）只给 Last Order，任何配置都不能把它交给一个执行者；反过来，执行类工具按模板给，Last Order 也可以有，只要它的模板节点写了。

Last Order 默认只有管理与消息工具，外加一个读取实例上下文末尾的工具：监督与取证都要看对方做过什么，没有这个工具就只能听转述。它是特权读——上下文属于实例，跨实例读取只给协调者，不给其他执行者。没有读文件、写文件、执行命令。

禁止命令列表先加上，用于装配与记录；是否在运行时拦截，按实际需要再定，不作为当前设计前提。

八消息与三条通路

通信由一个中心完成，单向投递，不含请求应答的配对语义。回复就是另一条消息。

三条通路：事件到实例、实例到实例、实例与 Last Order 之间（含人与 Last Order）。人的输入只由 Last Order 接收；Last Order 要把话交给某个实例时，自己发一条。

中心只认三件事：发送者身份、订阅条件、投递目标。它不知道卡片、项目、角色，也不解释内容。

投递规则：

  • 接收者空闲时逐条投递。
  • 接收者忙碌或消息密集时，按该接收者的最高触发频率合并；一批携带全部消息，顺序保留，每条保留原编号。
  • 合并只减少触发次数，不减少内容，不丢弃。
  • 重投按消息编号识别，同一条只进入上下文一次。

人不回复没有任何后果：消息留在中心，实例不被唤醒，Last Order 也不等待。人回复后那是一条新消息。

实例向 Last Order 求助分两步：先把问题发出去，再把卡片挂起。答复作为消息回到实例的会话，卡片从挂起回到就绪，继续原来的工作。发不出去就不挂起，避免卡片等一个没人收到的问题。

卡片结束时它的订阅在中心被撤销，配置留在卡片上；Last Order 自身的订阅挂在它的实例上，只在人要求时增删。

九上下文

实例运行期间持续使用历史。历史无损：原始记录完整保留、可检索、可展开。进入模型窗口的是被选入的内容与层级摘要，不是唯一的副本。

卡片结束时给这段历史打标签，标记为一次经历。实例保留，不因卡片结束清空。

两个独立动作：

  • 隔离：把选定的一段历史收在一个根节点下。此后的上下文组装默认不展开它；子内容完整保留，需要时检索。
  • 整理为技能：产生一条带适用范围与版本的方法，复核后生效。

两个动作可以由实例自己、Last Order、人或另一个实例发起。它们是动作，不是流程：系统不规定何时做、由谁做、做几次。

Last Order 的历史过深时换会话。新会话不带旧细节，当前状态从数据库读取；旧历史保留，按需访问。

十界面

界面只有两处：会话窗口与状态视图。

会话窗口是与 Last Order 说话的地方。人可以引用一张卡片或一个实例，引用之后 Last Order 看到被引用对象及其状态。

状态视图显示请求、卡片、依赖、实例、订阅。选中一张卡片时，它同时显示这张卡的路径范围、禁止命令与订阅，超出的部分给出剩余条数。它是只读的：数据来自数据库查询，不持有状态，不写任何表，不直接调用执行层。修改只能通过对话表达，由 Last Order 的工具落库。

只读是有意的：写入只有一个入口，才不会出现两处同时改同一事实。视图刷新即可看到最新状态。

命令行查询与图形视图是同一份数据的两处显示，用于没有图形界面的环境。

十一失败

情形行为
中心不可用本地动作照常；消息在发送端暂存，恢复后重投；重投按编号去重
实例异常终止记录一条事件；卡片可绑定另一个实例重新开始
启动与修改并发代次不一致时拒绝启动，由发起方重新读取后再提交
Last Order 会话过长换会话；状态从数据库读，历史保留
数据库不可用整个系统停止写；视图显示不可用；不做降级写入
卡片长期无进展系统不判定，也不介入；由人或 Last Order 决定是否取消
卡片挂起等输入由协调者恢复或取消；恢复把它放回依赖关系决定的位置，不需要重建卡片
向尚未启动的卡片发消息照样建立路由并投递；会话启动时按顺序读到，不因未启动而拒绝

十二必须成立的条件

  1. 每个实例依附一个模板节点；节点不可变；实例不随最新节点移动。
  2. 一张卡片在执行期只绑定一个实例；一个实例在同一时刻只服务一张卡片。
  3. 只有 Last Order 能创建模板节点、实例与卡片。
  4. 角色只决定身份特权：管理工具只给 Last Order，配置不能把它给执行者；能力由模板节点决定。
  5. Last Order 的默认工具集是建卡、模板与实例、上下文动作、技能候选、发消息、读实例上下文，不含文件与命令工具；节点可以显式增加，增加即记录。
  6. 模板决定能力，卡片决定范围，两者互不约束。
  7. 消息单向，中心不解释内容。
  8. 卡片结束时它的订阅在中心被撤销，卡片上的配置保留，恢复时按同一配置重新推送；Last Order 的订阅随其实例存在。
  9. 历史无损；窗口是选择，不是唯一副本。
  10. 产物属于项目；删除实例不删除产物。
  11. 视图只读；写入只有 Last Order 一个入口。

十三取舍与代价

选择理由代价
不做编排引擎拆分与验收是提示与模型的事，写死会把一种方法变成全部方法质量依赖提示与模型；系统不保证任务拆得对
实例不带覆盖差异留下可复现的记录小差异也要建节点，版本树会长
卡片五态只保留推进所需的规则无法表达“等待外部条件”这类中间状态，由实例空闲体现
消息单向不引入应答状态，失败面小调用方自己判断何时需要后续消息
中心独立投递是通用问题，复用已有实现依赖外部包与它的部署方式
数据库单机配置与状态同源不支持多机共享；扩容需要替换存储层
视图只读避免第二个写入者人不能在界面上直接拖线，必须通过对话

十四部署对架构的约束

中心是独立进程，因此架构必须允许它在另一台机器上运行：本机走本地通路，远程走加密的 HTTP，身份用令牌表达，不能依赖同机共享内存或文件锁。

数据库是单机文件，因此系统不提供多机共享同一份状态；需要多机时只能把整个数据目录放在同一台机器上，其余机器通过中心通信。

历史与产物都在本地目录，因此备份与迁移以目录为单位；中心只保存消息队列，不保存任务与历史。

Last Order 的会话是长连接进程，因此需要能被重启而不丢状态；重启后从数据库读取当前状态，从历史库读取上下文。
