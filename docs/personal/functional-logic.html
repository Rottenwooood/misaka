功能逻辑设计

系统里有哪些对象，每个对象在什么情况下做什么。不含结构分层，不含实现方案。

第一份，共三份　·　2026 年 11 月

一范围

系统的输入只有两种：人在 Last Order 的会话里说的话，以及已配置的订阅事件。系统不主动获取任何其他输入。

系统的输出只有两种：Last Order 与人之间的消息，以及实例在各项目目录中产生的文件与改动。

Last Order 是入口 agent。它不被赋予修改文件和执行命令的工具，只被赋予管理类工具。实例是执行者，行为由模板、提示和模型能力决定。

系统的职责是提供能力，不是规定方法。拆分、监督、验收如何做，不属于本文，也不进入机制。

二对象

对象是什么活多久
模板一类角色的默认配置：工具、技能、模型及其他会话配置。带版本，版本不可修改。长期维护
实例模板某一版本的实例，固定该版本，本身不带配置覆盖。拥有独立会话与历史、唯一编号与标签。可被多张卡片先后使用
请求人的一次要求，记录项目目录、目标文字、版本。到所有相关卡片结束
卡片一次子任务：任务描述、实例配置、文件系统范围、禁止命令、订阅。随任务结束
订阅一条投递规则：什么来源的什么类型，送到哪里。可增删改查。挂在卡片上则随卡片结束；挂在实例上则随实例
消息一次投递：发送者、接收者、类型、内容、编号、关联。持久保留
历史实例完整经历的无损记录。长期保留
技能一条可复用的方法，带适用范围与版本。长期保留，可修订

三输入到达之后

人说话，或订阅命中的事件到达 Last Order，Last Order 被唤起，进入一轮处理。它可以做四类事：向人发消息、创建或修改卡片、创建或修订模板、登记实例、管理订阅。它不能修改文件，不能执行命令。

处理结束时，它可以什么都不做，也可以留下卡片。卡片不会因为被写下而自动开始。

四卡片

用哪个实例（已有实例，或按下面三种输入新建）；文件系统范围；禁止命令；订阅；依赖的其他卡片；执行代次。

卡片有五个状态：待决、就绪、执行中、完成、失败、取消。状态只按允许的迁移变化。

  • 待决 → 就绪：全部前置卡片完成。
  • 就绪 → 执行中：被显式启动，且启动检查通过。
  • 执行中 → 完成 或 失败。
  • 未完成 → 取消。

前置失败、取消，都不算完成，因此不会让后续卡片就绪。

卡片没有“等待人”状态。人不回复时卡片保持原状，实例可能空闲，这不构成特殊状态，也不触发任何动作。

同一实例在同一时刻只服务一张卡片。需要并行时，另建实例。

五模板与实例

模板的版本构成一棵树：每个版本有父版本，修订可以基于任意已有版本，默认基于最新版本。版本不可修改，只能新增。

每个实例必须依附一个模板版本，实例本身不带配置覆盖。需要差异时，差异先成为一个版本节点，再由实例依附它。

创建实例有三种输入，都只产生一个实例：只给一个已有版本，直接建立实例；给一个已有版本加修改参数，先在该版本下建立新版本节点，再建立依附它的实例；给全部参数，从零建立版本节点，再建立依附它的实例。

只有 Last Order 能创建和修订模板、登记实例。

六权限：两件不同的事

模板配置的是“能做什么”：工具、技能、模型、会话相关设置。

卡片配置的是“能碰哪里”：文件系统范围，以及可选的禁止命令。

两者互不约束，不构成上下层。模板给的是能力清单，卡片给的是本次执行的范围与禁令。

Last Order 不能修改文件、不能执行命令，这一点由“不给它这些工具”实现，不需要额外的检查。

七消息与三条通路

通信由一个中心投递，单向，不包含请求与应答的配对语义。回复就是另一条消息。

  • 事件 → 实例：订阅命中即投递。
  • 实例 → 实例：按目标投递。
  • 实例 → Last Order，Last Order → 人，以及反向：都按目标投递。

投递规则：接收者空闲时逐条投递；接收者忙碌或消息密集时，按该接收者的最高触发频率合并，一批携带全部消息，顺序保留，每条保留原编号。合并只减少触发次数，不减少内容，不丢弃。

重投按消息编号识别，同一条只进入上下文一次。

人不回复时没有任何后果：消息留在中心，实例不被唤醒，Last Order 也不等待。人回复后，那是一条新消息。

订阅属于卡片时随卡片结束而删除；Last Order 自身的订阅挂在它的实例上，不随任何卡片结束。

八上下文与历史

实例运行期间持续使用历史。历史无损：原始记录完整保留、可检索、可展开；模型看到的是选入窗口的内容与层级摘要。

卡片结束时给这段历史打标签。实例保留，不因卡片结束而清空。

两个独立动作：隔离选定历史，把一段历史收在一个根节点下，此后的上下文组装默认不展开它；整理为技能，产生一条带适用范围与版本的方法。

两个动作可以由实例自己、Last Order、人或另一个实例发起。整理出的技能经复核后生效。

Last Order 的历史过深时更换会话。新会话不带旧细节，当前状态从系统记录读取。

九验收与监督

系统不定义验收由谁做、怎么做。系统提供三样能力，供 Last Order、人或另一个实例自行组合：读取任意工作区的文件；执行检查操作；创建一张验证卡片交给另一个实例。

卡片记录复核者与结论的位置，但不规定结论如何产生。结论是否影响卡片状态，由使用者决定，系统不强制。

十失败

实例异常终止时产生一条记录。卡片可以绑定到另一个实例重新开始。

卡片必须自足：离开某个实例的私有历史仍然能做下去。凡是只能依赖某个实例记忆才能继续的卡片，视为卡片没有写清任务。

十一不做的部分

  • 不规定任务如何拆分，不规定拆分粒度。
  • 不规定何时监督、监督到什么程度。
  • 不规定验收流程与验收者。
  • 不为人未回复设置超时、重试或状态。
  • 不为消息设置次数或时间上限。
  • 不做层层收窄的权限链。
